# 客户端用量采集器统一安装

签名发布就绪时可默认启用每日检查与静默升级；也可关闭。未配置签名发布的站点仍可普通安装，并每天提示手动升级。旧设备需执行一次签名安装命令进入自动升级流程。发布与升级操作见 [更新说明](usage-reporter-updates.md)。

个人后台“外部用量”提供一个“客户端用量采集器”入口。用户选择 macOS 或 Windows，勾选 Codex、Claude Code 或两者，生成一条限时安装命令，在客户端设备上执行一次即可。CLI 和官方 VS Code 扩展共用 Claude Code 采集器。

安装脚本只下载一次对应平台的 `usage-reporter`，随后自动配置所选采集器并注册后台任务。两种采集器仍每 5 分钟向网关上报；Windows 直接运行 GUI 子系统程序，输出追加到各自日志，无需每次上报时启动 PowerShell 窗口。首次主动运行安装命令的终端会显示安装结果。

## 用户操作

1. 登录网关，进入“外部用量”中的“客户端用量采集器”。
2. 选择系统及需要采集的客户端。管理员未启用的来源不能选择。
3. 按需选择自动升级；只有 HTTPS 和签名发布就绪时才展示该选项。两种客户端均无需填写 API 地址。Claude Code 自动识别进程的实际路由，排除本网关与已配置的网关别名，其他来源的模型用量直接上报。
4. 点击“安装所选采集器”，复制安装命令，在运行这些客户端的设备上执行一次。
5. 安装完成后，重启 Claude Code CLI 和 VS Code 中的 Claude 会话，使 telemetry 设置生效。

这一步安装的是用量采集工具，不安装 Codex、Claude Code 本身。当前自动采集支持 Codex 和 Claude Code；Cursor 仍通过管理员导入 CSV，不会因统一安装入口而自动获得采集能力。WSL、远程 SSH 和容器需在客户端进程实际所在环境部署采集器，Windows 主机接收器不能替代远程环境的接收器。

## 授权与已有安装

统一入口使用 `POST /api/external-usage/self/client-installer-command`，只为当前登录用户签发其选择且站点已启用的来源令牌。每种来源仍使用独立、单次、限时令牌；组合脚本下载前检查令牌来源、有效期、状态及用户一致性。下载脚本不会消耗令牌，实际安装时兑换。

签名托管安装共用 `runtime/releases/` 下的不可变版本与升级任务；来源配置和队列留在原位置。普通安装继续使用各自固定路径。Codex 与 Claude Code 保留独立设备记录、来源权限、配置、采集状态和后台任务，避免相互覆盖；设备数上限仍适用，选择两者需有两个来源设备记录的额度。相同用户和设备重装会复用原设备记录与有效凭据，两种采集器均保留网关排除规则、状态和待发送队列。

已有单工具安装无需先卸载，重新生成统一命令即可更新。未选择的采集器不会被卸载或修改。旧单来源安装接口保持兼容。

各来源安装独立报告结果。一种失败时仍尝试安装另一种，最终返回非零退出状态以避免误报全部成功；修正设置后重新生成命令重试即可。Claude 设置无效或已存在不兼容的遥测 helper 时，不会停止或替换原有 Claude 后台服务。详细配置、隐私与路由约束见 [Claude Code 安装说明](claude-code-usage-reporter.md)。

采集器公共模块及新增客户端接入方式见 [适配器说明](usage-reporter-adapters.md)。

## 验证范围

自动回归覆盖真实二进制的一次下载、双客户端安装、重装保留、部分失败、来源禁用、非法选择、跨账户令牌混用及来源令牌互换。前端验证包括无需地址的单选/双选、来源未启用及跨用户禁用。

Windows 脚本保留直接执行 GUI 二进制、日志和退出状态检查，已有 PE 子系统回归继续适用。Windows 计划任务与实际无闪窗体验仍需实机验收。
