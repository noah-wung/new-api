# 客户端采集器自动检查与静默升级设计

状态：签名升级模块已实施，但用户随后决定暂不配置自动升级，当前改用每日检查、通知用户手动升级。普通安装无需签名配置；以下保留原设计作为后续启用参考。当前行为与验证范围见 [更新说明](../../installation/usage-reporter-updates.md)；本设计不代表已经生产部署。

基线：`codex/claude-code-usage-reporter`，`949da3b1b`。

## 1. 目标与范围

Codex、Claude Code 共用一套版本检查、下载、验证、切换、恢复和状态回传机制。后续客户端只声明运行方式及健康条件，不复制升级流程。用户一次选择需要采集的客户端，后续升级只更新已安装的来源，不安装或启用新的来源。

首版覆盖当前已有安装目标：macOS arm64 / amd64、Windows amd64。保持每 5 分钟上报；Codex 仍由系统任务定时执行，Claude 仍常驻接收。Linux、WSL、远程容器不在本次支持范围内。

自动升级不改变网关地址、用户身份、上报凭据、网关过滤规则、Claude 路由声明、接收端口、本机接收令牌和 telemetry 配置。不通过升级扩大采集权限。

## 2. 当前实现及必须处理的差异

| 现状 | 设计处理 |
| --- | --- |
| 统一安装下载同一份程序，但两来源各有配置、状态和任务 | 共用版本目录与升级任务，来源配置和任务继续独立 |
| 没有独立采集器版本；`client_version` 指被采集工具版本 | 增加 `reporter_version`、构建提交和兼容版本，不覆盖现有字段 |
| 安装脚本覆盖固定路径二进制 | 新安装改用不可变版本目录，切换系统任务引用 |
| Codex 重装重签凭据 | 同网关、同用户、同设备、同来源且旧凭据有效时复用；自动升级始终不兑换安装令牌 |
| 队列目录含服务器与凭据摘要 | 保持原配置、目录、事件 ID、ACK 收据和拒绝记录，禁止跨身份搬迁 |
| Claude 接收器不可在升级前停止后长时间等待下载 | 下载与预检均在旧进程运行时完成，仅切换阶段短暂停收 |

依据：`service/client_usage_installer.go`、`service/external_usage_installer.go`、`service/claude_usage_install_script.go`、`pkg/usagereporter/claude_install.go`、`pkg/usagereporter/reporter.go`。

## 3. 用户体验与默认策略

| 项目 | 默认行为 |
| --- | --- |
| 自动更新 | 安装界面默认勾选“自动检查并静默更新”，安装前明确展示，可取消 |
| 检查周期 | 首次启用后 0–10 分钟内检查；成功后每 24 小时检查一次，增加 0–60 分钟随机延迟 |
| 唤醒/重新登录 | 检查已到期时补做一次，不补跑所有错过的周期 |
| 网络失败 | 15 分钟、1 小时、6 小时后重试，其后每 6 小时重试，附加随机延迟；不影响采集任务 |
| 本地版本切换失败 | 恢复旧版，同一个发布 ID 自动隔离，不循环切换；需新发布 ID 或用户主动重试 |
| 下载和切换 | 全程后台运行；Windows 使用 GUI 子系统程序，不调用可见终端，无 UAC 提权 |
| 权限或杀毒拦截 | 保留旧版并记录错误，后台显示待处理，不自动弹窗或要求提权 |
| 用户关闭自动更新 | 停止版本检查和安装；状态仍可在用量上报时回传，采集不停止 |

升级任务每 15 分钟被系统唤起一次，根据私有状态中的 `next_check_at` 决定是否发起网络检查，因此正常情况下每天只检查一次。恢复未完成事务优先于自动更新开关，但只恢复已授权的旧事务，不发起新升级。

“立即检查/升级”首版提供本机命令，输出写入日志或指定结果文件；个人后台展示操作指引和状态。后台远程推送命令不在首版范围内，避免让用户误以为点击后可立即唤醒离线设备。

## 4. 公共模块与平台差异

新增 `pkg/reporterupdate` 公共模块，统一完成：

- 版本和清单验证、目标平台与兼容性判断、时间调度和下载限额。
- 安装范围锁、事务日志、回滚、失败版本隔离和清理。
- 生成每来源的任务切换计划；以声明式来源清单识别已安装来源。
- 更新状态文件、来源状态回传，不读取对话正文或原始日志。

对外仅暴露三个业务入口：检查并准备、应用已验证计划、恢复未完成事务。下载文件本身或任意路径不构成可应用计划；入口必须重新核验本地计划与签名。

平台 Adapter 负责系统任务的读取、暂停、启动、恢复、权限和进程退出确认。macOS 使用用户 LaunchAgent；Windows 使用当前用户 Task Scheduler 和原生进程能力。来源 Adapter 只声明轮询/常驻、配置路径、任务身份、启动参数和健康条件；路径从本机已安装记录读取，服务端清单不能指定任意本地路径或命令。

更新感知版本增加本机生命周期控制：macOS 使用私有 Unix socket，Windows 使用只允许当前用户访问的命名管道，支持健康查询及优雅退出。退出请求先取消上传/扫描、完成已进入持久化阶段的工作，再释放队列和进程锁。不能把 Windows 的 `Stop-ScheduledTask` 当作优雅退出。生命周期控制由公共层提供，来源只响应既有 context 取消。

不引入必须常驻的新管理进程，也不把自更新逻辑放进每个来源的采集循环。

## 5. 安装布局与身份隔离

保留已有文件位置：

```text
~/.new-api-usage-reporter/
  config.json                         # Codex：保留
  state.json / state.json.usage-queue/ # Codex：保留
  claude/                             # Claude：保留配置、state 和 .claude-queue
  runtime/
    releases/<release_id>/<target>/usage-reporter[.exe]
    staging/<transaction_id>/
    installation.json                 # 网关绑定、随机安装 ID、已安装来源、自动更新开关
    update-state.json                 # 当前/上一版本、下次检查、错误代码、发布序号
    transaction.json                  # 断电恢复依据，不含上报凭据
    update.log                        # 限大小轮转日志
```

配置和队列不移进版本目录。新安装两来源引用同一份版本二进制；单独安装一种也使用同一结构。旧固定路径程序在迁移验收后停用，不再被旧任务调用。

首版一套用户目录绑定一个网关 origin，支持该网关下已有的独立来源凭据。发现配置混用不同网关时拒绝自动接管并保留现有任务；多网关安装不在本次范围。升级不能改变绑定，不能自行迁移到另一个网关。

元数据不复制凭据，凭据仍仅存在各自私有配置中。macOS 使用私有目录与文件权限；Windows 明确设置当前用户及必要系统主体 ACL，不沿用宽松继承权限。锁使用操作系统可随进程退出释放的机制，不依赖文件时间认定活进程已失效；另有持久事务记录用于恢复。

## 6. 版本、签名和发布契约

采集器拥有独立 SemVer（如 `1.0.0`）和 Git commit；协议版本、队列/状态格式版本单独记录。服务端网关版本不直接代替采集器版本。发布 ID 唯一，发布序号严格递增；同版本不能悄悄覆盖二进制。

发布流水线为三个目标编译程序，Windows 保留 GUI 子系统，注入版本信息。生成 SHA-256、字节数及 Ed25519 签名清单。建议的清单字段：

| 字段 | 语义 |
| --- | --- |
| `schema_version`, `key_id`, `catalog_sequence` | 清单格式、受信签名密钥、部署目录序号 |
| `issued_at`, `expires_at` | 签发和失效时间，过期不启动新升级 |
| `release_id`, `reporter_version`, `commit` | 不可变发布身份与可读版本 |
| `report_protocol_min/max`, `config_schema_min/max`, `state_schema_min/max`, `queue_schema_min/max` | 可接受的服务端协议和各本机格式范围 |
| `targets[]` | 每目标的 artifact 相对路径、SHA-256、字节数 |
| `rollout_percent`, `rollout_seed`, `paused` | 此次签名部署的灰度规则 |

清单封装为 base64 原始 payload 字节与签名，直接对原始字节验签，避免 JSON 重排导致签名差异。限制清单 64 KiB、单目标程序 100 MiB；超时、实际大小或摘要不符即丢弃下载。首版分发单个可执行文件，不解压任意归档。

明文私钥只在受控发布环境内存中使用，不进入源码、客户端、容器镜像或网关数据库。标准 age 加密私钥和公钥可随源码管理，解密口令独立保存在系统 Keychain 或 CI Secret，不写明文私钥临时文件。网关只导入并分发已签名发布目录和二进制，启动/激活时校验签名、资产完整性和平台齐全性；缺少资产禁止激活。自动更新接口不临时执行 `go build`，避免同一版本返回不同文件。

公钥在首次受信安装时固定，后续不得从清单下载后直接信任新公钥。密钥轮换需旧受信密钥授权新密钥并预留重叠期；旧密钥全部失效后的恢复需人工重新建立信任。

生产建议使用 HTTPS；内网 HTTP 分发必须有独立可信渠道校验首次安装包/公钥指纹。仅在同一 HTTP 安装脚本中放入公钥不能抵御首次安装被替换。后续更新始终验签，不通过关闭 TLS 验证解决证书问题。HTTP 也不允许携带上报凭据或状态接口令牌；需要状态回传时应配置 HTTPS。

自动检查仅信任绑定网关的清单。下载只允许该 origin 内受限的发布资源相对路径，拒绝跨域跳转、路径穿越及任意下载地址；不向其他地址发送凭据。

## 7. 服务端接口及权限

沿用 `Router → Controller → Service → Model` 分层。拟新增接口：

| 接口 | 权限与用途 |
| --- | --- |
| `GET /api/external-usage/reporter/updates/stable` | 公开、限流；返回当前签名部署清单或无发布，不接收设备凭据 |
| `GET /api/external-usage/reporter/releases/:release_id/:target/:name` | 公开、限流；仅不可变且存在的发布资产；不含用户信息 |
| `POST /api/external-usage/reporter/status` | 现有专用设备凭据；仅回传该凭据对应设备和来源的更新状态 |
| `GET /api/external-usage/self/reporter-status` | 当前登录用户，仅查询自己设备的状态 |
| `/api/external-usage/admin/reporter-releases/*` | 管理员；验证并激活预置的签名发布目录、暂停分发、查询发布记录 |

清单和已知发布资源与来源是否被禁用解耦，便于修复/回滚；状态及用量回传仍校验设备有效性、来源权限和站点策略。公开下载不授予任何上报权限。状态接口不信任请求中的 user/device ID，而从凭据解析身份，并限制字段长度和枚举值。

管理员接口只接受已部署发布 ID，不能传服务器任意文件路径或执行签名命令。发布激活、暂停操作沿用管理员操作审计。多副本网关使用同一已验证资产集，激活指针统一持久化；找不到资产的副本返回不可用，不能回退到不匹配的其他文件。

首版只支持 `stable` 通道，提供管理员暂停和按签名清单 10%→50%→100% 灰度。安装 ID 为本机随机值，以其与 rollout seed 的哈希稳定分桶，不新增硬件指纹，也不把该 ID 发送到公开清单接口。灰度比例变更须签发更高序号清单；同 seed 扩大比例，避免设备反复进出分组。

客户端记录已见清单最高序号及其摘要，拒绝较低序号或同序号不同内容。自动安装仅接受高于当前 SemVer 的版本；新的灰度清单可以提高目录序号而不修改发布二进制。无兼容发布、过期、未知签名、时钟明显异常或服务器返回 404 时继续旧版；不自行安装历史版本。暂停可即时阻止新检查获取发布，已离线准备好的计划不保证被瞬间撤回；应用前必须在线重取当前有效清单，否则延后。

事务内回滚仅允许恢复本机事先记录并验证过的上一可用程序，属于恢复操作，不降低已见清单序号，也不允许从网络重新下载任意低版本。管理员需要撤回已提交的版本时发布更高 SemVer 的修复构建。

## 8. 升级事务与恢复

```text
idle → checking → downloading → verified → prepared
     → switching → health_check → committed
                         ↘ rolling_back → rolled_back / recovery_required
```

1. 持有安装级更新锁，优先恢复旧事务；自动开关关闭或未到期时结束。
2. 获取清单、验签、检查平台/版本/协议/格式及灰度；无更新即记录下次检查。
3. 下载到安装目录同一文件系统的 staging，校验签名对应摘要、大小和目标平台。此时采集照常运行。
4. 用候选程序执行不修改数据、不联网的自检，读取所有已安装来源配置和兼容性；拒绝格式不兼容或扩大来源的计划。
5. 重取部署清单确认仍获准；记录旧任务定义、旧版本、受影响来源、事务 ID 和恢复步骤，持久化后安装独立恢复任务。
6. 启动由已验证旧版执行的独立 apply helper。Windows 脱离原任务 Job 生命周期、隐藏运行；macOS 使用独立临时用户 LaunchAgent，避免卸载原更新任务时终止 helper。helper 只接受本机私有且重新验证过的事务计划。原检查进程完成启动握手后释放更新锁，helper 获取锁并核验事务 ID 后接管；其他检查进程见到未完成事务只能进入恢复入口，不能并发开始另一事务。恢复入口对刚准备好的事务预留 30 秒接管宽限，过期未接管再恢复。
7. 暂停本次涉及的采集任务的后续触发，阻止新的 Codex 轮询；通过本机生命周期控制等待现有任务退出，Claude 做有界优雅退出、等待正在处理的请求落盘。上限 30 秒，退出未完成则取消本次切换并恢复任务触发，不强杀正在写队列的进程。确认退出后才调用可能强制结束进程的系统卸载/停止动作。
8. 将已验签候选程序落入不可变版本目录，逐个更新来源任务引用并启动；全部来源作为一次事务，不能留下双来源长期处于混合版本的成功状态。
9. 每来源执行健康验证，之后切换公共更新任务到新版路径。更新器本身也按版本目录更新，不覆盖正在执行的 `.exe`。
10. 所有健康条件满足后提交事务；取消临时 apply/recovery 任务，保留最近一个已知可用版本。执行失败或进程崩溃时恢复全部旧任务。

恢复任务固定引用旧版不可变路径，独立于候选程序；切换前创建并校验可运行，5 分钟后首次到期、之后每分钟重试，且在重新登录时也可触发。它先尝试获取同一安装锁：helper 仍工作则退出等待下一次唤起；锁可获得且事务未提交则恢复旧任务。正常升级有 120 秒整体应用时限，超时进入恢复。若掉电重启，原锁释放，恢复任务读取持久事务后继续；已提交的事务仅清理遗留临时任务。

恢复过程本身须幂等，恢复任务定义成功后再解除暂停，最后验证旧版健康。恢复也失败时保留事务和旧文件，标记 `recovery_required`，后续恢复任务重试并在能通信时回传状态；不能误报升级成功。

回滚前也必须确认候选进程已退出；若候选无响应且无法安全释放队列或接收端口，保留文件并进入 `recovery_required`，不能启动第二个写同一队列的进程。长期无响应不能仅靠持有锁阻止恢复：apply helper 的系统执行上限为 3 分钟，系统可结束管理 helper 以释放管理锁，但不连带结束采集 worker；后续恢复按进程与任务真实状态处理。

### 平台应用方式

- macOS：系统任务直接引用版本目录的可执行文件；切换时保留原用户域、Label、参数和日志路径，由独立 helper 完成 bootout/bootstrap。旧程序不改名覆盖。
- Windows：计划任务直接引用版本目录 `.exe`；停止并确认退出后，更新任务 Action，保持当前用户、Limited 权限、触发器及隐藏执行。旧文件继续存在，避免占用导致替换失败。
- 两平台均仅操作安装记录中的任务，检查运行进程身份，不扫描或按进程名批量结束其他用户进程。不允许自行提升到管理员/root。

## 9. 健康验证与数据连续性

候选程序提供不触碰队列的配置/格式自检。进入实际切换后：

- Codex：配置可读、原状态/队列可打开、可读取已配置采集位置；完成一次正常轮询。公网/网关不可达属于上传失败，仍保留事件，不据此判断程序损坏；原有离线状态与“从健康变损坏”需区分。
- Claude：保持原 loopback 地址和接收令牌，确认成功监听、队列可读写、接收和上传 worker 已启动，并持续观察至少 60 秒。增加仅限本机认证的健康查询，不注入虚假用量事件。
- 健康响应/收据绑定事务 ID、来源和候选 release ID，防止误把旧进程、旧状态文件或无关端口当作成功。
- 没有用量的设备也能通过健康检查；不以必须成功上传一条用量作为条件。

切换和回滚绝不清空队列、不重置扫描游标、不轮换凭据。沿用已有稳定事件 ID 和服务端去重；已持久化且未确认的数据继续重试。不能简单恢复升级前的队列快照，否则可能覆盖新确认/新入队事件。

首版只允许新旧两个版本双向兼容的配置/状态/队列格式，禁止不可逆自动迁移；不满足则标记需人工升级。回滚恢复程序和任务引用，不恢复已继续推进的数据文件。未来破坏性格式升级必须单独设计，不能仅提高 SemVer 后自动放行。

Codex 的源日志可重扫，Claude 的 OTLP 导出在切换期间可能暂时连接失败；导出器是否保留/重试取决于客户端实现。因此承诺保留已落盘数据、缩短停收时间，不能承诺 Claude 切换期间绝对零丢失。该窗口须纳入实机验收记录。

## 10. 失败策略及空间清理

| 场景 | 行为 |
| --- | --- |
| 断网、下载中断、无兼容版本 | 不停旧版，按检查重试策略延后 |
| 签名/摘要/平台/协议校验失败 | 不执行候选，记录确定错误代码；安全校验失败不绕过 |
| 磁盘不足、权限不足、文件被杀毒锁住 | 不切换或恢复旧任务，不删除队列腾空间 |
| 任务更新只完成一半 | 事务日志驱动全部来源回滚 |
| 更新器/apply helper 崩溃或掉电 | 独立恢复任务重放恢复步骤 |
| 候选崩溃、不能绑定 Claude 端口 | 恢复旧版并隔离该 release ID |
| 切换提交后才发现业务问题 | 管理员发布更高版本修复；历史降级不自动执行 |
| 原设备凭据被撤销 | 不签发替代凭据、不换账号；保留本地数据，状态回传按授权失败处理 |

新下载前检查可用空间，预留候选程序和至少 20 MiB 管理余量，不把空间检查视为能保证写入成功。保留当前、上一可用版本及任何未结束事务引用的版本；其他版本在提交后清理。staging 遗留在无活动事务时清理。删除失败下次重试，不影响采集，不能删除现用或恢复任务引用的文件。

更新日志只记录版本、阶段、时间和受控错误代码；不记录凭据、对话、用户目录绝对路径及服务端任意错误正文。日志轮转总计默认不超过 10 MiB。

## 11. 后台展示与存储

个人后台“外部用量”设备列表增加：采集器当前版本、可用版本、最近检查、自动更新开关的最近回传值、更新阶段、最近错误、状态回传时间。明确标记过期状态和“不支持自动更新的旧采集器”；没有新字段不能推断为最新版。

自动更新开关在安装命令中传递并落本机安装配置，是本机公共安装级设置，对已接管的所有来源一致生效；安装界面明确说明该范围，不远程修改其他设备，也不接管未选择的旧来源。后续通过本机管理命令开关。后台只显示最近观测值，不能把“生成命令时勾选”当作设备已经启用。

新增设备更新状态表，按已有 `device_id` 唯一关联，保存最新值而非无限增长的心跳日志；不改用量事件的既有 `client_version` 语义。多来源分别用各自凭据上报；共享版本不合并设备权限。私有状态回传失败不阻断采集或升级，恢复通信后发送最新状态。

状态在升级阶段变化后尝试回传，并在采集上报路径中最多每 24 小时回传一次（包括空用量设备）；已停用来源不上传。HTTP 网关只保留本地状态，不明文发送凭据；后台提示未获得状态及 HTTPS 配置要求。

新增表及发布指针必须通过 GORM 支持 SQLite、MySQL、PostgreSQL；前端使用现有 i18n，补齐六种语言。仅有客户端上报的版本属于设备自报状态，不作为服务端安全授权依据。

## 12. 旧设备接入与重新安装

没有自更新能力的旧采集器不能被服务器升级自动触达。管理员上线新版网关后，用户需要最后执行一次新版安装命令，建立版本目录、信任公钥和升级任务，之后才进入静默升级。

迁移只接管用户这次选择且已安装/获授权的来源；如果另一来源尚未接管，保持其原任务和固定程序。共享升级任务只管理安装记录明确列出的来源。选用新安装工具后才注册的来源随公共版本走，不将旧任务误判为已迁移。

重新安装分清两种情形：

1. 同身份、有效凭据：安装兑换校验当前登录用户、设备摘要、来源和网关，复用现有凭据。Codex 补齐与 Claude 对应的复用流程，保留网关排除规则及全部状态。
2. 旧凭据无效、切换账户或网关：不把旧队列自动挂到新身份，不无提示覆盖旧配置；保存旧安装并明确报告需处理身份迁移。首次安装仍正常申请设备凭据。

整个首次迁移也使用准备、暂停、切换、健康检查和恢复流程，并留有旧任务与程序以便回滚。由于旧版不具备恢复命令，首次迁移的 helper 和恢复任务由本次受信安装包中具备更新能力的程序执行，回滚目标仍是原程序与任务，不能让旧版执行其不认识的恢复参数。

旧版尚无本机生命周期控制：Codex 停止后续触发并等待当前轮询自然完成；macOS Claude 通过 SIGTERM 优雅退出。旧 Windows GUI Claude 无法依赖控制台信号优雅结束，首次手工迁移可能需要系统停止任务，存在在途 telemetry 重试窗口；只承诺保留已落盘队列，安装结果明确记录这次迁移。此例外仅用于用户主动执行的旧版迁移，不用于后续正常静默升级。

重新安装在读取旧配置后只修改用户明确选择的新字段，保留自定义采集路径、状态路径和所有网关排除规则，不能按默认值重建已有配置。新增 Claude 来源仍需要明确路由配置及重启 Claude 会话；日常二进制升级不重写 telemetry，通常无需用户重启 CLI 或 VS Code。

## 13. 确认后的实施顺序及验收

实施顺序：

1. 增加独立版本信息、签名发布产物、服务端只读发布接口与部署资产验证。
2. 实现公共更新模块、操作系统锁、版本布局、apply/recovery 事务及两平台 Adapter。
3. 接入统一安装与旧任务迁移，补齐 Codex 有效凭据复用，保留旧单来源入口兼容。
4. 增加受限设备状态接口、后台展示与 i18n，接通自动检查开关。
5. 在最终集成分支完成完整测试和两平台实机验收，形成发布资产后再安排灰度；本设计确认不等于授权生产部署。

必要验证：

- 两来源同装、单装、分次安装，后续来源接入不重复实现升级代码；未选择来源不被安装、停止或改写。
- 同身份迁移凭据不变，扫描游标、过滤规则、Claude 地址/令牌、队列、`.confirmed`、拒绝记录在升级和回滚后正确延续。
- 升级前存在积压和部分 ACK，升级后仅继续处理未确认数据，跨账号不混用；网关用量排除回归必须通过。
- 验签失败、摘要失败、过期/重放、未知密钥、错误目标、跨域跳转、路径穿越、不兼容格式都不能执行候选。
- 对各持久事务阶段做确定性故障注入，覆盖部分任务切换、helper 崩溃、断电后恢复和恢复自身再次中断。
- Windows 实机验证无窗口闪烁、无 UAC、运行中文件不被覆盖、登录补跑和更新器自身切换；macOS 实机验证 helper 不受原 LaunchAgent 卸载影响。
- 没有用量、没有联网、磁盘不足、端口占用、凭据撤销、来源禁用和用户关闭自动更新的实际行为。
- Go 单测、相关 race/vet、三目标构建与 Windows PE GUI 检查；前端 typecheck/lint/build 和交互测试；数据库迁移与状态权限在三种数据库中验证。
- Claude 连续事件输入场景记录切换停收窗口和客户端重试表现，不能只验证进程还在运行。

## 14. 建议确认的决策

建议按以下默认决策进入实施：自动更新默认开启且安装前可关闭；每天检查、每 5 分钟用量上报；公共升级任务配合独立 apply/recovery；签名校验与版本目录切换；保留有效凭据和双向兼容的数据格式；旧设备最后手工执行一次迁移安装；首版 stable 通道与管理员灰度，后台展示状态而不远程强推执行。

内网 HTTP 的首次可信安装和凭据传输限制需在实际发布时满足第 6、11 节要求。设计未承诺新增操作系统或自动处理跨身份迁移，也未承诺 Claude 停收窗口零丢失。
